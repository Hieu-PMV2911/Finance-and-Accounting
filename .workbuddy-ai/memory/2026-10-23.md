### Bugs found and fixed while implementing (all were silent failures)

1. `@iconify-json/*` CJS entry exports a **wrapper** `{ icons: <doc>, info, metadata, chars }`
   while the ESM entry exports the document directly. `mod.default ?? mod` picked the
   wrapper → `set.icons` was the doc (6 keys) instead of the 1,978-icon map → every icon
   "unknown". Fixed with `toIconifySet()` normaliser + `failure()` to surface load errors.
2. `transformIndexHtml` must be `order: 'post'`. With `'pre'` the registry is empty (Vite
   processes index.html before transforming modules) → sprite never injected, build green.
3. Standalone sprite file needs `xmlns="http://www.w3.org/2000/svg"`. Without it the file
   parses in no namespace, external `<use href="sprite.svg#id">` renders nothing while the
   network tab shows 200. Now always emitted.
4. SVGO 4: returning `null` from a visitor does **not** remove a node — `<script>` survived
   sanitisation. And splicing during `enter` corrupts the traversal (next sibling skipped,
   so `onclick` survived). Fix: collect doomed nodes, remove in `root.exit`.
5. Minified chunks use backticks (`href:`#smart-icon-x``), so `href="` never matched when
   rewriting hrefs for file mode. Match the quote char instead: `/(["'`])#smart-icon-/g`.
6. `list()` returned only `icons`, excluding `aliases` — Lucide renamed `home`→`house` and
   keeps `home` as an alias, so "did you mean" could never suggest the name that works.
7. Rolldown **forbids** adding keys to the bundle in `generateBundle`
   ("This plugin assigns to bundle variable … ignored"). Emit the sprite asset from
   `transformIndexHtml` (post) via `this.emitFile({fileName, source})` instead; mutating
   `item.code` of an existing chunk is allowed.

### Fourth pass — Svelte 5 verified end-to-end

Svelte was the highest-risk untested path: its scanner is the one that previously failed
silently (F4 — walker found nothing, build stayed green).

- **`@sveltejs/vite-plugin-svelte` v6 does NOT support Vite 8** (`peer vite@^6.3.0 || ^7.0.0`).
  Vite 8 support starts at **v7.3.1** (`peer vite@^8.0.0`, `svelte@^5.46.4`). Documented as F21.
- **Real bug found (F20)**: Svelte's attribute `Text` node spans only the value **between**
  the quotes, unlike JSX/HTML where the range includes them. The scanner emitted

  `Expected token >`. Fixed with `quote: ''`. Only a real Svelte build could catch this —
  the unit test had only asserted `specifier`/`attr`, never the range semantics.
- Icons themselves were correct on the first Svelte build: paired tag
  `<icon-lucide-home …></icon-lucide-home>` range covers the whole element and replaces
  cleanly; self-closing works too.
